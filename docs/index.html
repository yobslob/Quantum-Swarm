Quantum Swarm

An adaptive quantum-inspired swarm optimiser. It builds on QPSO, watches its own swarm every iteration through a Swarm Diversity Index and an Improvement Rate, raises α only when the swarm is stuck, and gives stuck particles a tunnelling jump.

What we learned

1 · The controller needs a stagnation gate

A converging swarm and a stuck swarm both have low diversity. The first (ungated) design raised α whenever SDI dropped below δ = 0.05, which kept pushing the swarm apart while it was still improving. The gate g(t) raises α only after IR has stayed below η for W/2 iterations.

α during one run (Rastrigin, D = 30, seed 7)
Swarm Diversity Index (dashed = δ)

2 · Optimum-at-origin benchmarks can mislead

Five of the six classical functions have their minimum at the centre of the box. GWO looks best there, but once the optimum is shifted away from the centre it falls to the bottom of the table, because its update pulls wolves towards the origin (Niu et al., 2019). QPSO and Quantum Swarm barely move.

Friedman rank: classical vs shifted (D = 30, lower is better)

3 · Ablation: what each component does

One component removed at a time (D = 30, 30 runs). Signs compare the full Quantum Swarm against each reduced version.

Code

Python 3.10+, NumPy, SciPy and Matplotlib. Each file is one module from Chapter 4 of the report.

Reproduce
# install
pip install -r requirements.txt

# one demonstration run (Figure 6.1)
python demo.py --function Rastrigin --dim 30 --seed 7

# the full study: 3,825 runs → results/results.json (≈ 2–3 min on 4 cores)
python experiments/run_experiments.py

# report figures → results/figures/
python experiments/make_figures.py
